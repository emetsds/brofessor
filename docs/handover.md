Ручная r2 и принятый checkpoint сохранены после контролируемого сбоя публикации. Loader на стандартной библиотеке, без нового framework/таблицы/зависимости.

## Версии, режимы и ресурсы последнего опыта

Mac M4, 32 GiB; `mlx-audio==0.6.3`, `mlx==0.32.4`. Инференс полностью локальный: HF/Transformers offline, запрет `socket.connect`, явные локальные пути. Веса/кодеки скачивались отдельным явным шагом с закреплёнными revisions и проверками SHA-256/Git hashes.

| Конфигурация | Закреплённая ревизия |
|---|---|
| Fish 4-bit | `majentik/fishaudio-s2-pro-MLX-4bit@dda28aa6e33fe946826792e3feb643e9c463b75f` |
| Fish codec, BF16 при исполнении | `mlx-community/fish-audio-s2-pro-8bit@c8d4481b3f7cbfe64d855c8b7cda7739502fc3ff` |
| OmniVoice BF16 + FP32 Higgs codec | `mlx-community/OmniVoice-bfloat16@6119f7072580cc30c3cbdf496269216b03ad9742` |
| VoxCPM2 8-bit | `mlx-community/VoxCPM2-8bit@d52725898a0675703f7f9ddc5a4d1a3cdbb99032` |

Fish: строгая загрузка семантических весов с изолированной поправкой quant predicate для реально квантованных embedding/fast layers; BF16 codec с weight-norm folding. Reference VQ-коды приготовлены отдельным процессом и переиспользуются в штатном reference conversation. Не менять установленные библиотеки ради повторения опыта. Temperature/top_p 0,7, top_k 30, speed 1, stream interval 1 с.

OmniVoice: 32 diffusion steps, guidance 2, ru; native resample/RMS boost/удаление тишины, все слова reference и transcript сохранены. Длительность оценивается штатным `RuleDurationEstimator` по фактическому темпу reference tokens; generic fallback установленного MLX использует фиктивную английскую фразу и здесь не применяется. Полные опоры немного длиннее рекомендации авторов 3–10 с; сравнение с короткими не делалось.

VoxCPM2: 10 timesteps, cfg 2, native continuation **`prompt_audio` + `prompt_text`**. Generic `ref_text` в установленном runtime игнорируется. Старые остановки на 30,080 с были в другой конфигурации с синтетическими опорами; они не повторились в этом общем сегментированном опыте, но длинный единый вызов с Dialogs не проверен.

|---|---:|---:|---:|
| Fish | 4,45 GB | 5,18 GB | 5:32 → 18:57 |
| OmniVoice | 2,04 GB | 4,88 GB | 5:12 → 10:03 |
| VoxCPM2 | 3,23 GB | 9,16 GB | 5:06 → 21:38 |

**Модели работали параллельно**, одновременно выполнялся CPU ASR. Эти времена не являются изолированным benchmark и не доказывают соотношение скоростей одиночного запуска. Пик MLX не равен полной RAM/RSS процесса/машины. Диск — минимальный набор выбранной конфигурации, без старых snapshots/неиспользуемых весов предыдущих опытов. Загрузка, скачивание, ASR и упаковка не входят в время синтеза. API-расходов нет; энергопотребление не измерялось.

## Что интегрировано в продукт

CLI и Streamlit — равные клиенты общих сервисов. Python 3.12, uv, Pydantic, SQLite, один OS-locked detached worker на проект; без отдельного HTTP/queue/framework. Исходники, стабильные локаторы, ревизии, заметки, checkpoints и принятые аудиосегменты сохраняются. Проекты живут отдельно от приложения. Вопросы используют оригинальные цитаты; чтение целой книги для медиа проверено на полном EPUB. Есть длинные подкасты, серии, RU/EN UI и PPTX через `python-pptx` без Node/npm.

Kokoro RU и Silero RU сохранены в каталоге совместимости, загрузчике и рендере старых заданий. Kokoro работает через pinned RUAccent + ONNX/IPA frontend, extra `russian-speech`; Silero RU v5.6 — CPU, native accent/ё flags. Подготовка сохраняет draft, ё и ручные `+`/acute, записывает отдельный `synthesis_text`; версии ресурсов и runtime входят в кеш. Не возвращать сетевой `RUAccent.load()` и не устанавливать ресурсы в site-packages. Пять pinned helper-файлов материализованы рядом с данными из-за `__file__.resolve()` на HF blobs. [Реализация и проверки](experiments/kokoro-silero-ru.md).

UI после согласованной переработки: рабочая область проекта и связанные результаты, поиск/фильтры/страницы, читаемый просмотр, обычные поля редактирования, JSON в дополнительном режиме, история, источники и заметки. Рендер заблокирован при несохранённом/устаревшем буфере; `service.render(revision=...)` и CLI `draft render --revision` фиксируют показанную редакцию при конкурентной правке. [Browser/offline-проверки и ограничения](experiments/ui-redesign.md).

Не ломать frozen inputs/idempotency: повтор одинакового render переиспользует job и принятые сегменты в CLI/UI. Изменение голоса/расшифровки/настроек меняет ключ, описание каталога — нет; явный `--request-key` сохраняет первый snapshot. Неуспешное задание с прежними входами продолжают через `job resume`. Ревизии сохраняются с expected revision через core, а не прямой правкой SQLite/JSON. Обычный UI rerun/закрытие браузера не останавливает worker.
