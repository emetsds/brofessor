## Намерение пользователя и принятые решения

Пользователь делает личную замену NotebookLM. Книги — основной первый сценарий, но проект объединяет любые поддерживаемые источники и связанные результаты: вопросы, ответы, заметки, сценарии, аудио и презентации. Название всегда **brofessor**, с маленькой буквы.

- Подкасты на русском и английском, минимум два голоса, целевая длительность 20–60 минут, серии по большим материалам, собственный промпт для фокуса.
- Редактируемые презентации со своим фокусом. Для v1 реализован PPTX; Google Slides отложен за v1.
- Равноправные CLI и Streamlit UI; общие сервисы и данные. Интерфейс RU/EN, выбор сохраняется вне проекта.
- Текст через официальные Codex CLI, Claude Code CLI или Ollama. Исходный личный бюджет — существующая ChatGPT Pro и локальные модели; Pro не является API-балансом или способом оплатить TTS API. Claude использует собственную авторизацию; настоящая проверка с имевшейся подпиской уже выполнена.
- Проекты хранятся отдельно от приложения; модели речи выбираются и скачиваются из UI/CLI в общий пользовательский кеш.
- Пользователь регулярно просит KISS-ревью. Не добавлять новые движки, оболочки, универсальные workflow/plugin frameworks или инфраструктуру ради будущих возможностей. SQLite, один отдельный worker и необходимые гарантии сохранности уже осознанно выбраны.
- Реализация, тесты и документация поручены агенту. Обратимые технические шаги не требуют повторных согласований. Push, remote, публикация, покупки и глобальные настройки требуют соответствующего запроса. Исходный код — MIT по выбору пользователя; чужие веса имеют свои лицензии.

Redirects и inherited HTTP proxies выключены. `OLLAMA_NO_CLOUD=1` нужен **серверу**; установка переменной только клиенту не меняет сервер. Непроверенный сервер нельзя незаметно обходить. Нет автоматического cloud/API fallback.

Добавлены сценарии закреплённой редакции готового PPTX, сбоя/timeout/отмены MP3 с сохранением предыдущего файла и сегментов, запрета пересылки источника при HTTP redirect, настоящей границы F5 с подставленной upstream-библиотекой, гонок выбора голоса и общих повторов CLI/UI. Шесть временно внесённых дефектов обнаружены; смена прямоугольных блоков на скруглённые тесты не ломает. Правила качества тестов добавлены в AGENTS.md. Процент покрытия и количество тестов не являются целью.

Исправлен реальный баг: UI вычислял ключ render отдельно от фиксации голоса, поэтому под ключом A могло оказаться задание с голосом B. Теперь `service.render` вычисляет ключ из тех же frozen inputs, которые получает worker. Одинаковый render переиспользует задание в **CLI и UI**; изменения голоса/расшифровки/настроек меняют ключ, описание каталога — нет. Явный `--request-key` сохраняет первый snapshot даже при конкурентной отправке; новая строка ключа создаёт отдельное задание. Для неудачного задания с прежними входами используется `job resume`, не повторный submit.

Последняя полная проверка: **355 passed**, Ruff check/format и `git diff --check`. Прогон был в core + UI без torch/f5_tts/soundfile/mlx_audio. Настоящие модели в этой работе не запускались. Исторические отчёты с 340/362 тестами относятся к предыдущим срезам и не являются текущим счётчиком.

## Команды и окружение

Если существующее окружение готово, запускать из корня без переустановки:

```sh
cd /Users/demets/src/brofessor
uv run --no-sync pytest -q
uv run --no-sync ruff check .
uv run --no-sync ruff format --check .
uv run --no-sync brofessor --help
```

Для нового окружения только core + UI: `uv sync --locked --python 3.12 --extra ui`. `uv sync` выбирает extras для текущего окружения; если нужно сохранить все TTS в существующем dev-venv, использовать `--extra ui --extra speech --extra silero --extra f5`. Не переустанавливать/скачивать гигабайты без необходимости. Node/npm не устанавливать. CI использует Python 3.12, core + UI и DejaVu; обычные тесты не требуют сети/подписок/весов.

Для безопасного экспериментального запуска выбрать отдельный workspace, свободный UI-порт и отдельные `XDG_CONFIG_HOME`/`XDG_DATA_HOME`. Указывать одинаковые переменные во всех процессах тестового профиля; не полагаться на их сохранение между tool calls. Не делать `tts use`/`project use` на пользовательских настройках ради QA. Не останавливать пользовательские UI 8501 и Ollama 11434. Их состояние в новом чате нужно проверить заново; временные процессы прошлых экспериментов не считаются живыми.

Стабильные official CLI могут отличаться от первого `codex` в PATH. Проверять выбранный executable, при необходимости использовать `BROFESSOR_CODEX_BIN`/`BROFESSOR_CLAUDE_BIN`, затем `doctor`. Не читать credentials. Проверенные в M4 версии: Codex 0.162.1, Claude Code 2.1.185, Ollama 0.40.6. Local-only текстовый профиль проверен на `qwen3.8:27b-q4_K_M` на Mac с 32 GiB; маленькие Qwen3 4B/Qwen2.5 7B не приняты по качеству русского контента. Это результаты эксперимента, не обещание текущей доступности/универсальной пригодности.

CLI по умолчанию использует запомненный проект; для QA явно передавать `-w /absolute/workspace`. `doctor` может завершиться с кодом 0 и `available: false` — читать JSON. `--wait` возвращает ненулевой код для неуспеха. `draft show` выдаёт envelope, редактировать нужно только `data` и сохранять с expected revision. Рендер закрепляет сохранённую редакцию на момент submit; `job resume` не подхватывает последующие правки. `artifacts[].path` разрешается относительно workspace.
