# Требования к brofessor

Состояние: 06.11.2026. Основание: обсуждение продукта с пользователем и последующие команды продолжить реализацию.

## Назначение и подтверждённые решения

brofessor должен стать заменой NotebookLM для личной работы с источниками. Пользователь изучает материалы, задаёт вопросы и создаёт на их основе результаты. Книги - основной первый сценарий, но предметная модель не ограничивается книгами.

Подтверждено пользователем:

- Название `brofessor`, всегда с маленькой буквы. Отдельный локальный репозиторий с перспективой публикации на GitHub.
- Подкасты длительностью от 20 минут до часа, в том числе серии по большому материалу. Пользователь задаёт фокус своим промптом.
- Русская и английская озвучка, несколько голосов.
- Штатная озвучка для нового пользователя работает без самостоятельной подготовки аудиореференсов и ручного подбора тембра. 03.11.2026 пользователь одобрил пятиминутный русский диалог Qwen3-TTS Base с готовой парой ExNihilus и выбрал этот метод дефолтным. Модель и лицензированные образцы скачиваются вместе. У кода и весов Qwen Apache-2.0, у образцов ExNihilus CC0. Для RU и EN используются отдельные пары из этого набора.
- Презентации с отдельным пользовательским фокусом, результат в PPTX или Google Slides.
- Базовый личный сценарий использует уже имеющуюся подписку ChatGPT Pro и бесплатные для выбранного использования локальные модели на Mac.
- Независимость от агента: поддержать Codex, Claude, Ollama и открытые модели.
- При добавлении UI интерфейсы CLI и UI должны быть равноправны. Пользователь предложил Streamlit. Этот план включает локальный Streamlit UI в первую версию.
- Проект — набор источников и связанных с ними результатов переработки, по модели работы NotebookLM. Пользователь выбирает проект, чтобы вернуться к его материалам и результатам.
- Проекты можно хранить отдельно от приложения, в выбранной пользователем папке.
- По уточнению 06.11.2026 скачивание моделей в UI запускается только в общих настройках. В проекте остаётся выбор модели и переход к настройкам при отсутствии файлов. Размер, актуальное состояние и продолжение прерванной загрузки доступны после повторного открытия настроек; затем пользователь возвращается к тому же сценарию.
- После KISS-аудита 03.11.2026 в обычном выборе оставлен один поддерживаемый метод Qwen Base с ExNihilus. Старые профили доступны по точному ID для воспроизведения исторических заданий.
- Для текста через Ollama пользователь может указать IP и порт сервера на другом компьютере. Источники передаются выбранному серверу; TTS и рендер PPTX остаются на компьютере приложения. По умолчанию используется 127.0.0.1:11434. Проверка отключённых cloud-функций и установленных весов сохраняется.

Технические решения и критерии ниже предложены агентом для реализации. Они не означают, что пользователь отдельно утвердил каждый инструмент или численный порог качества.

04.11.2026 пользователь поручил реализацию перевода книг с сохранением оформления, иллюстраций и профессиональной терминологии, затем продолжение после пробы. Для раннего EPUB 3 реализован общий CLI/UI-путь с автоматическим словарём значений, необязательными пользовательскими предпочтениями, версионностью и точечной коррекцией связанных фраз. [Проверено на синтетической главе](experiments/book-terminology.md); полноценная приёмка целой книги и PDF этим не заявляются. Остаток объёма — в P1 плана. Слуховая приёмка отложена до сигнала пользователя.

Следующее продолжение добавило EPUB 2/NCX, стандартный XHTML DOCTYPE и сохранение namespace scopes. [Целое руководство W. Stanley](experiments/epub-reader-compatibility.md) переведено, полностью сверено и открыто в EPUB.js; вычитанная r2 содержит правки 44 из 213 блоков. После исправлений выполнен [полный автоматический контроль workflow 3 и 4](experiments/epub-recurring-terms.md): 213 блоков без ручных правок, дополнение пропущенных повторяющихся терминов, 76 значений / 295 употреблений, сверка смысла и просмотр EPUB. Это одна небольшая книга; остались локальная грамматика и неполнота anchors. Последующая PDF-проверка описана ниже. Метаданные, структура, исходные картинки и маркированные notices сохраняются; текст внутри растра не переводится.

## Область первой версии

05.11.2026 добавлен путь перевода текстового PDF через те же worker/CLI/UI, словарь, редакции и модели задачи. После [первой двухколоночной страницы](experiments/pdf-translation.md) выполнен [контроль целой авторской PDF-книги](experiments/pdf-whole-book.md): 31 страница, 262 блока, 64 значения / 542 употребления, r1 без ручной редактуры. Исправлены смешанные шрифты/лигатуры, текст вложенных схем без дублей, оглавление с номерами, плотные ячейки, переносы/пробелы и положение подписей/команд. Весь перевод сверен, все страницы просмотрены после растеризации, независимый аудит фактического PDF прошёл; 352 сохранённые области, графика/картинки и 44 назначения ссылок сохранены. Переполнение и неподдержанная структура получают явный отказ. Это одна небольшая реальная книга в ограниченном классе; произвольная inline-математика, сложная геометрия и большие учебники не приняты. Общий процесс EPUB/PDF не подтверждает автоматически качество любого документа.

Первая версия замыкает цикл: создать постоянное пространство → добавить несколько источников → изучить их и получить ответы со ссылками → задать фокус → подготовить и отредактировать сценарий/слайды → получить подкаст и PPTX → вернуться к результатам и пересобрать нужную часть.

Это первый законченный набор сценариев, а не заявление о полном паритете со всеми возможностями NotebookLM.

05–06.11.2026 по прямой команде выполнить весь план, кроме личной приёмки, реализованы R18–R20 в CLI/UI. Настоящий Codex проверен на коротком синтетическом EPUB: справочник с принятой терминологией, разбор аргументации, четыре вопроса и объяснения четырёх контролируемых ответов. Локальный Qwen Base собрал короткую двухглавую аудиокнигу, сохранённый перевод подготовлен к озвучиванию без потери извлечённых слов. Это не слуховая приёмка и не гарантия качества целой аудиокниги. [Проверки и ограничения](experiments/additional-formats.md).

04.11.2026: после критического разбора реализован явный экспериментальный способ написания длинных подкастов с возвратом к оригиналам, сохранением различий источников и состояния разговора. Контрольный опыт не обосновал смену обычного метода по умолчанию. Для любого сохранённого сценария доступна отдельная проверка смысла ссылок: pinned revision/model, exact excerpts, частичный отчёт, недостаточный контекст, отмена/продолжение в UI/CLI. Проверка не заменяет редактуру и не блокирует озвучку автоматически. [Результаты и ограничения](experiments/episode-writing.md).

Параметры определяет действие. Создание проекта принимает имя и расположение, открытие — папку или недавний проект. Поиск работает с оригинальными фрагментами без текстового исполнителя. Новая задача получает параметры выбранного формата и копию общих моделей; применимые модели можно переопределить в задаче. Уточнение ответа и выпуск серии наследуют контекст родителя. При создании пользователь задаёт язык генерации.

Правка отдельной реплики с пробой голоса доступна по желанию. Обычный путь ведёт от сценария к готовому выпуску. Незавершённый текст восстанавливается после закрытия браузера. Сохранение версии остаётся явным, входом для пробы и сборки служит выбранная сохранённая редакция.

05.11.2026 по запросу пользователя добавлена коллекция источников по пути к каталогу, включая Obsidian. Подключение сохраняет только путь: без отбора файлов, индексации, конспектов и модельных вызовов. По промпту задачи приложение просматривает каталог, ищет, читает оригиналы и следует внутренним ссылкам. Версии/локаторы доступны после изменения или отключения каталога; новая задача видит текущие материалы. Полное чтение проверяет все извлекаемые фрагменты запрошенной области. Работают прежние поддержанные форматы; запросы Obsidian/Dataview и код документов не исполняются. [Проверки и границы](experiments/collection-navigation.md).

## Что означает поддержка исполнителей

- **Codex:** официальный CLI runner для заданий из CLI/UI с собственным входом пользователя в Codex.
- **Claude:** Официальный Claude Code CLI runner. Подписка Claude у владельца не предполагается и не приобретается автоматически.
- **Ollama:** сервер инференса по выбранному IP:порту, которым управляет фиксированный workflow brofessor. По умолчанию сервер на этом же компьютере; пользователь может выбрать другой компьютер. Наличие Ollama не означает наличие агентного цикла, навыков или разрешения на shell.
- **Открытые модели:** как минимум одна модель текста и одна модель речи проходят настоящий сквозной тест на целевом Mac. Совместимость определяется конкретными моделью, размером, квантованием, лицензией и runtime. Поддержка всех весов/архитектур не обещается.

Каждая интеграция получает один из статусов: planned, implemented, contract-tested, smoke-tested. Только последний означает проверку настоящим инструментом и доступным аккаунтом/моделью. Требуемая, но непроверенная интеграция остаётся незавершённой задачей полной приёмки. Это не блокирует личное использование уже проверенных профилей и не требует покупать Claude-подписку для продолжения разработки.

## Критерии качества

- Во всех типах задач крупные разделы имеют различимые заголовки, видимые горизонтальные границы и возможность сворачивания. Вложенные примечания, подписи полей и метаданные подчинены заголовкам. Готовый файл, материал, предметные источники/проверка и служебные настройки различимы; перед настройками видно окончание материала, в том числе после последнего слайда. Сворачивание сохраняет ввод, выбранный элемент и редакцию; существенные ошибки и действия сохранения остаются доступны. Это требование проверяется на каждом типе задачи и его истории, а не только на сценарии подкаста.
- Все локаторы в выдаче разрешаются в сохранённый оригинальный источник. Валидный ID не доказывает, что источник подтверждает тезис: отдельно проверяется смысловое соответствие.
- На небольшом размеченном корпусе проверяются минимум 20 вопросов/утверждений, включая середину длинного источника, конфликт версий, несколько документов и отсутствие ответа. Утверждения, которых нет в источниках, не выдаются как факты источника.
- Для подкаста измеряется длительность готового аудио. Предлагаемый допуск к запросу - 10% при сохранении диапазона 20–60 минут. Нельзя добирать время пустыми повторами или молча обрезать смысловой блок.
- Два голоса стабильны между репликами и на новых текстах. Новый пользователь получает рабочие дефолтные голоса без подготовки аудиообразцов и ручного проектирования тембра; подписи голосов должны соответствовать фактическому звучанию. Нет смысловых пропусков, зацикливаний и обрывов. Произношение имён, чисел и терминов проверяется на пилоте. Предлагаемый порог локальных исправлений - не более 5% реплик.
- Слайды открываются в доступном редакторе, рендерятся и проходят визуальный просмотр. Текст и заявленные редактируемые объекты действительно изменяются.
- CLI/UI проверяются одной матрицей сценариев. Закрытие вкладки, повторная отправка формы и одновременное управление не дублируют дорогое выполнение.
- Скорость часового выпуска и субъективный уровень качества не обещаются до измерений. Агенты выполняют технические проверки, пользователь может выбрать предпочтительный тембр по коротким образцам.

## Границы первой версии

Google Slides и дополнительные форматы источников остаются за первой версией. Они не требуют отдельной инфраструктуры сейчас. Публичный хостинг, аккаунты, совместное редактирование, универсальные плагины и отдельный протокол работы skills не входят в реализацию.
