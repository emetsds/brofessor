# Требования к brofessor

Состояние: 01.11.2026. Основание: обсуждение продукта с пользователем. Начата реализация первого рабочего среза.

## Назначение и подтверждённые решения

brofessor должен стать заменой NotebookLM для личной работы с источниками. Пользователь изучает материалы, задаёт вопросы и создаёт на их основе результаты. Книги - основной первый сценарий, но предметная модель не ограничивается книгами.

Подтверждено пользователем:

- Название `brofessor`, всегда с маленькой буквы. Отдельный локальный репозиторий с перспективой публикации на GitHub.
- Подкасты длительностью от 20 минут до часа, в том числе серии по большому материалу. Пользователь задаёт фокус своим промптом.
- Русская и английская озвучка, несколько голосов.
- Презентации с отдельным пользовательским фокусом, результат в PPTX или Google Slides.
- Базовый личный сценарий использует уже имеющуюся подписку ChatGPT Pro и бесплатные для выбранного использования локальные модели на Mac.
- Независимость от агента: поддержать Codex, Claude, Ollama и открытые модели.
- При добавлении UI интерфейсы CLI и UI должны быть равноправны. Пользователь предложил Streamlit. Этот план включает локальный Streamlit UI в первую версию.

Технические решения и критерии ниже предложены агентом для реализации. Они не означают, что пользователь отдельно утвердил каждый инструмент или численный порог качества.

## Область первой версии

Первая версия замыкает цикл: создать постоянное пространство → добавить несколько источников → изучить их и получить ответы со ссылками → задать фокус → подготовить и отредактировать сценарий/слайды → получить подкаст и PPTX → вернуться к результатам и пересобрать нужную часть.

Это первый законченный набор сценариев, а не заявление о полном паритете со всеми возможностями NotebookLM.

| ID | Требование и граница первой версии | Проверяемый результат |
|---|---|---|
| R01 | Постоянные пространства с выбранными источниками, заметками, вопросами и производными материалами | После перезапуска доступны источники, история и результаты. Пространство можно перенести на другой каталог/компьютер без исходного агента |
| R02 | Импорт PDF с текстовым слоем, EPUB, Markdown и TXT | Сохраняются оригинал, хеш, версия, структура и локаторы. Дубликаты распознаются. Неподдерживаемые/повреждённые источники получают явный статус |
| R03 | Полнота обработки больших материалов | Каждая извлечённая страница/раздел учтена как обработанная, исключённая с причиной или проблемная. Пустое извлечение не считается успехом |
| R04 | Поиск и вопросы по одному или нескольким выбранным источникам | Ответ содержит проверяемые ссылки. Для недостатка данных и противоречий есть явное представление. Поддержан вопрос на русском к английскому источнику |
| R05 | Управление фокусом и редактурой | Сохраняются аудитория, язык, промпт, акценты и редакционные исключения. Ручные правки создают новую версию и не теряются при пересборке |
| R06 | Подкасты и серии | Целевая длительность 20–60 минут, минимум два различимых голоса, RU и EN. Для запроса обоих языков по умолчанию отдельные версии. Серии имеют общий план и согласованные термины |
| R07 | Презентации | Редактируемые текст, таблицы и простые схемы в PPTX, заметки докладчика и ссылки на источники. Иллюстрации могут быть растровыми. Полноэкранная картинка не заменяет редактируемый слайд |
| R08 | Равноправие CLI и Streamlit UI | Оба интерфейса выполняют одни операции и видят одни данные. Задание можно создать в одном, наблюдать, отменить и продолжить в другом |
| R09 | Независимость от агента и модели | Общие контракты работают с Codex CLI, Claude Code CLI и Ollama. Смена исполнителя не требует повторного импорта |
| R10 | Продолжение и отмена работы | Закрытие UI не прекращает worker. После аварии сохраняются законченные этапы и аудиосегменты. Отмена прекращает дочерние процессы задания и запуск новых этапов |
| R11 | Явные расходы и передача данных | Нет автоматического платного fallback. Локальный профиль не отправляет материал в облачные модели. Подписка Codex не считается универсальным API-ключом |
| R12 | Воспроизводимость и переносимость установки | Установка не зависит от библиотек, тайно поставляемых конкретным desktop-агентом. Версии инструментов, моделей и лицензий фиксируются для проверенных конфигураций |

## Что означает поддержка исполнителей

- **Codex:** официальный CLI runner для заданий из CLI/UI с собственным входом пользователя в Codex.
- **Claude:** Официальный Claude Code CLI runner. Подписка Claude у владельца не предполагается и не приобретается автоматически.
- **Ollama:** локальный сервер инференса, которым управляет фиксированный workflow brofessor. Наличие Ollama не означает наличие агентного цикла, навыков или разрешения на shell.
- **Открытые модели:** как минимум одна модель текста и одна модель речи проходят настоящий сквозной тест на целевом Mac. Совместимость определяется конкретными моделью, размером, квантованием, лицензией и runtime. Поддержка всех весов/архитектур не обещается.

Каждая интеграция получает один из статусов: planned, implemented, contract-tested, smoke-tested. Только последний означает проверку настоящим инструментом и доступным аккаунтом/моделью. Требуемая, но непроверенная интеграция остаётся незавершённой задачей полной приёмки. Это не блокирует личное использование уже проверенных профилей и не требует покупать Claude-подписку для продолжения разработки.

## Критерии качества

- Все локаторы в выдаче разрешаются в сохранённый оригинальный источник. Валидный ID не доказывает, что источник подтверждает тезис: отдельно проверяется смысловое соответствие.
- На небольшом размеченном корпусе проверяются минимум 20 вопросов/утверждений, включая середину длинного источника, конфликт версий, несколько документов и отсутствие ответа. Утверждения, которых нет в источниках, не выдаются как факты источника.
- Для подкаста измеряется длительность готового аудио. Предлагаемый допуск к запросу - 10% при сохранении диапазона 20–60 минут. Нельзя добирать время пустыми повторами или молча обрезать смысловой блок.
- Два голоса стабильны между репликами. Нет смысловых пропусков, зацикливаний и обрывов. Произношение имён, чисел и терминов проверяется на пилоте. Предлагаемый порог локальных исправлений - не более 5% реплик.
- Слайды открываются в доступном редакторе, рендерятся и проходят визуальный просмотр. Текст и заявленные редактируемые объекты действительно изменяются.
- CLI/UI проверяются одной матрицей сценариев. Закрытие вкладки, повторная отправка формы и одновременное управление не дублируют дорогое выполнение.
- Скорость часового выпуска и субъективный уровень качества не обещаются до измерений. Агенты выполняют технические проверки, пользователь может выбрать предпочтительный тембр по коротким образцам.

## Границы первой версии

Google Slides и дополнительные форматы источников остаются за первой версией. Они не требуют отдельной инфраструктуры сейчас. Публичный хостинг, аккаунты, совместное редактирование, универсальные плагины и отдельный протокол работы skills не входят в реализацию.
