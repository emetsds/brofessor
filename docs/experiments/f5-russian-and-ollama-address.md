# F5-TTS Russian, упрощение и адрес Ollama

Проверено 02.11.2026 на Apple Silicon Mac с 32 ГБ памяти. Новый F5-профиль использует существующий движок, очередь, образцы голосов и монтаж. Зависимости и lock не менялись.

Автоматический RUAccent не подключён. Взята документированная v2; файлы winter в этой проверке не использовались.

Модель скачана настоящим download job в общий пользовательский кеш вне checkout. Существующие английский `f5-tts` и русский `espeech-rl-v2` сохранены. Новый профиль ограничен `ru`: английский draft отвергается до enqueue. Образцы host/guest и точные расшифровки фиксируются обычным model snapshot задания.

Настоящий синтез F5-TTS 1.1.22 / Torch 2.15.0 на Metal создал двухголосый русский фрагмент длительностью **8,826 с**; рендер занял **62,029 с**. Использованы сохранённые синтетические голосовые образцы предыдущей проверки, не сторонние личные записи. Выполнение прошло под временным macOS-профилем с запретом внешней сети и offline-переменными Hub/Transformers. Дополнительная ASR-модель не требовалась. MP3 полностью декодирован FFmpeg; повторный render переиспользовал оба сегмента. Это короткий smoke test, не приёмка часового выпуска, произношения или предпочтительного тембра.

## Три замечания KISS

1. Новые аудиозадания больше не обходят каталог через произвольный `repo@revision` или папку. Неизвестная модель даёт понятную ошибку CLI до создания job. Известные pinned specifications и уже сохранённые jobs поддерживаются; старый resolver остаётся на исполнении прежних jobs без снимка. История и старые данные не переписываются. Поздняя проверка установленности оставлена: CLI может поставить render следом за ожидающим download в том же worker.
2. В Create показываются только параметры выбранного результата: минуты для подкаста/серии, количество слайдов для презентации, число выпусков для серии. Вопрос не получает ни одного из этих полей. Их значения сохраняются при переключении, а нерелевантные значения не меняют fingerprint повторной отправки вопроса. Проверка проходит и после посещения других форм с изменёнными настройками.
3. Из архитектуры убран дублируемый справочник CLI. Примеры остаются в README и `--help`; исправлены ошибочный `--after`, несуществующие FTS5/doctor checks и устаревшее число движков. Фактический поиск — BM25, состояние — SQLite.

## Ollama по IP:порту

В CLI/UI `--ollama-address` заменяет `--ollama-port`. По умолчанию `127.0.0.1:11434`; можно указать IPv4 `192.168.1.20:11434` или IPv6 `[::1]:11434`. Адрес нормализуется до enqueue, сохраняется в job и участвует в checkpoint identity. Follow-up и эпизод наследуют адрес родителя. Неверный или незавершённый адрес Ollama в UI не мешает запуску другого текстового провайдера.

URL со схемой, credentials, путём, query/fragment, hostname без IP и порты вне 1–65535 отвергаются. Redirects и inherited HTTP proxies остаются выключенными. Перед передачей исходного текста сервер должен подтвердить отключённые cloud-функции и установленную локальную модель, без remote model metadata/aliases. Doctor показывает `address`, `cloud_disabled_verified` и `auth_mode: server_no_auth`: это не утверждение, что сервер находится на компьютере клиента. UI и README явно указывают, что источник обрабатывается выбранным сервером, а озвучка и PPTX остаются на компьютере приложения.

Старые jobs с `ollama_port` продолжают ходить на `127.0.0.1` и сохраняют прежние checkpoint keys; это проверено отдельно для стандартного и нестандартного портов. Обновление не меняет пользовательский Ollama, не запускает его и не открывает UI на внешнем интерфейсе.

HTTP contracts проверены для loopback, LAN IPv4 и IPv6, включая запрет передачи источника при включённом облаке. Дополнительно настоящий TCP/HTTP-прогон и установленный wheel подключились к временному синтетическому API на частном LAN-интерфейсе этого Mac: status, tags, show, streaming response. Это не настоящий Ollama на другой физической машине; такая машина в прогоне не использовалась. Тестовый API не обслуживал файлы, команды или пользовательские модели.

Веса, зависимости и пользовательские настройки в этот каталог не копируются. Содержательная и слуховая приёмка из M4 остаётся открытой.
