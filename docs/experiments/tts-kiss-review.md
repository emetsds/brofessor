# KISS-аудит вариантов озвучки

03.11.2026 пользователь попросил независимого субагента-критика проверить KISS, предложить число вариантов и помочь очистить технический мусор. Критик прочитал правила, требования, handover, каталог и реализацию речи, затем повторно проверил выбранное упрощение.

## Решение

Оставлен **один пользовательский профиль — qwen3-base с ExNihilus**. В нём мужская и женская роли с отдельными образцами для русского и английского. Этот метод выбран пользователем после прослушивания.

Восемь предыдущих профилей помечены как legacy и скрыты из списка CLI и обычного UI. Выбрать их постоянным дефолтом нельзя. Старые настройки с таким профилем разрешаются в Base. Сохранённые задания используют свой прежний снимок. Технические lookup, скачивание по точному ID и явный рендер старой моделью доступны для воспроизведения. [Восстановление старой озвучки](../legacy-speech.md)

Сильный аргумент за второй вариант — CPU-озвучка на слабой машине или рядом с большой Ollama. Base требует Apple Silicon и в проверке занимал около 7 GiB MLX-памяти. Пользователь выбрал Base, а отдельное требование на CPU-режим не подтверждено. Поэтому второй публичный метод сейчас увеличивал бы число вариантов для неподтверждённого сценария.

## Упрощения

- Убрана недостижимая в обычном UI форма загрузки F5-референсов и расшифровок. Команды `tts voice` сохранены для восстановления и скрыты из обычной справки.
- Основной README описывает выбранный путь. Инструкции по старым профилям вынесены отдельно.
- ID дефолта определяется в `speech_models.py`. Дубли repo/revision в `media.py` удалены.
- Классификация legacy исключена из идентичности рендера. Она не меняет ключи уже созданных сегментов.
- Исправлен найденный критиком крайний случай. Старый сохранённый spec без поля legacy мог сообщать об успешном выборе профиля, который фактически не становился дефолтом. Теперь `use` проверяет принадлежность активным ID каталога.

Адаптеры и необязательные extras прежних движков сохранены для выполнения исторических jobs. Критик не рекомендует объединять CustomVoice и Base в один условный адаптер — их внешние контракты различаются. Удаление поддержки старых снимков конфликтовало бы с восстановлением и переносом проектов.

## Очистка

Удалены 104 технических файла суммарным логическим объёмом **284 739 325 байт**, примерно 285 MB / 271,55 MiB.

- Архив Vosk `outputs/soft-vosk-2026-11-03/model.zip`, 135 298 234 байта. До удаления проверены опубликованный MD5 и размер/CRC всех соответствующих распакованных файлов.
- Дубль весов `outputs/kokoro-silero-ru/v5_6_ru.pt`, 147 664 410 байт. Его SHA-256 совпадает с установленным экземпляром общего кеша, который сохранился.
- Три скрипта неудавшейся VoiceDesign-пробы без аудио и ссылок из документации.
- Четырнадцать исторических PID-файлов после проверки отсутствия соответствующих процессов.
- Генерируемые Python/test/lint-кеши и пустые каталоги незавершённых Range-загрузок.

Подробные пути, причины, размеры и SHA-256 записаны в [журнале очистки](../../outputs/tts-kiss-review/cleanup.json). Логический размер удалённых файлов не равен гарантированному изменению свободного места APFS. Крупные снимки Qwen имеют несколько hardlink на общие данные, их нельзя считать независимыми копиями по выводу `du`.

## Проверки

После изменений прошли **385 offline-тестов**, Ruff check/format и diff check. Семь повторяющихся UI-случаев выбора устаревших профилей заменены проверкой единственного поддерживаемого пути. Защита общего скачивания и восстановления остаётся в `test_speech_models.py`, `test_f5.py` и `test_silero.py`.

Добавлены проверки публичного списка, старой/неизвестной сохранённой настройки, cached spec без legacy, неизменности идентичности исторического рендера и явного вызова скрытой команды голосов. Критик повторно проверил исправление старого cached spec в отдельном временном профиле и не выявил новых конкретных регрессий.

Дефолтный Base установлен и выбран. Принятый MP3, исходные WAV, проектные SQLite, голосовые образцы и остальные результаты опытов сохранены.
