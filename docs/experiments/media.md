# Локальные renderer и медиа-пилот

Дата проверки: 01.11.2026. Синтетический источник: `tests/fixtures/chapter.md`, специально написанный для brofessor. В пилоте нет личных материалов, внешнего TTS API и клонирования реальных голосов.

Этот отчёт сохраняет результаты исходного пилота. Затем PPTX-рендерер заменён на Python; Node/npm и их lockfile удалены из проекта. Текущее состояние и новая проверка описаны в [замене PPTX-рендера](python-pptx.md). Аудиотракт этой заменой не затронут.

## Зафиксированный профиль

- Apple M4, 32 GiB unified memory.
- Python 3.12, `mlx-audio==0.6.3`, `mlx==0.32.4`, `soundfile==0.14.0`, `imageio-ffmpeg==0.7.0`. Python зависимости закреплены в `uv.lock`.
- Единственный проверяемый TTS-кандидат: `mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-4bit`, ревизия `08c72cad5e2fd0f41730c8bd1f28149585e46361`, Apache-2.0. Предустановленные голоса: host = Ryan, guest = Vivian. `ru` передаётся как Russian, `en` как English. Референсные записи не используются.
- `generate_custom_voice`, streaming с интервалом 1 сек, seed 42, temperature 0.7, предел 1500 токенов на реплику. Достижение предела приводит к ошибке и не публикуется как успешный сегмент. Реплики длиннее 1000 символов требуется разделить в сценарии.
- Node.js 26, `pptxgenjs==4.0.1`, `image-size==2.0.4` через override. Последний устраняет обнаруженные npm advisory в transitive image parser. `npm install` после обновления сообщил 0 vulnerabilities. Lockfile сохранён. Используются только native text/table objects, без изображений.

Основания: [MLX-Audio v0.6.3 API](https://github.com/Blaizzy/mlx-audio/blob/v0.6.3/mlx_audio/tts/models/qwen3_tts/qwen3_tts.py), [Qwen3 CustomVoice model card](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-4bit), [PptxGenJS](https://gitbrent.github.io/PptxGenJS/docs/quick-start/), [image-size advisory](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq). Модель и runtime проверяются фактическим запуском, совместимость других checkpoints не заявляется.

## Контракт и восстановление

CLI и UI используют `brofessor.media.render_slides` и `render_audio` через общие application services. Модуль не зависит от интерфейсов.

Аудиосегмент имеет ключ из полного текста, языка, preset voice, закреплённой модели, версии runtime/renderer и настроек генерации. Возобновление проверяет JSON metadata, SHA256 WAV и корректность PCM. Повреждённый или изменённый сегмент синтезируется повторно. Цитаты хранятся в плане, а не озвучиваются как ID. Готовые сегменты переживают отмену. Проверка отмены выполняется между streaming chunks, репликами и стадиями сборки. Worker исполняет renderer внутри своего процесса. Запрос отмены из CLI/UI не прерывает принудительно загрузку модели или блокирующий MP3 encode: callback обнаружит его после возврата текущего блокирующего вызова. Мгновенная отмена этих стадий пока не реализована.

Итоговый WAV собирается потоково с паузами 250 мс. Длительность измеряется по фактическим PCM frames. FFmpeg из PATH или обычного пакета `imageio-ffmpeg` создаёт MP3 160 kbit/s. Без FFmpeg функция возвращает доступный WAV и явное предупреждение. Скорость воспроизведения и пустые повторы не используются для достижения целевой длительности.

При первом обращении разрешённого speech workflow скачивается выбранная публичная модель с Hugging Face. Последующий запуск может быть offline через `HF_HUB_OFFLINE=1`. В sandbox Codex отсутствует доступ к Metal, настоящий пилот выполнен с разрешённым доступом вне sandbox. Это ограничение окружения проверки, не требование запуска пользовательского приложения с повышенными системными правами.

## Настоящий Qwen3-TTS пилот

Скачивание публичных весов в отдельный `HF_HOME` заняло 116 с. Все приведённые ниже генерации запускались с `HF_HUB_OFFLINE=1`, без сети и без повторного скачивания. Время включает локальную загрузку модели и сборку WAV/MP3. Первый запуск также включал холодный импорт библиотек.

| Прогон | Реплик | Длительность аудио | Wall time | Peak allocated MLX memory |
|---|---:|---:|---:|---:|
| Короткий RU | 2 | 10.09 с | 34.907 с | 2.756 GB |
| Короткий EN | 2 | 9.13 с | 3.231 с | 2.756 GB |
| Связный RU | 8 | 124.07 с | 41.361 с | 2.804 GB |
| Связный EN | 8 | 121.67 с | 40.113 с | 2.804 GB |

Это измерения одного устройства и сценария. Peak MLX memory не равен полной resident memory процесса. Два связных выпуска содержат факты, числа и ограничения синтетической главы. Сценарии сохранены рядом с результатами в `episode-ru.plan.json` и `episode-en.plan.json`. Все 20 реплик завершили синтез, предел генерации не достигнут. Все WAV содержат конечные ненулевые данные. Для связных выпусков RMS равен 0.1019 / 0.0855, peak amplitude 0.9481 / 0.8990. Все четыре MP3 полностью декодируются FFmpeg 7.1 без ошибок.

Повторная сборка реальных коротких образцов внутри sandbox без доступа к Metal заняла 0.069 с для RU и 0.031 с для EN. Все сегменты были переиспользованы, модель не загружалась. Контрактные тесты дополнительно проверяют изменение preset voice и model revision и очистку незаконченного сегмента.

MLX-Audio/Transformers при загрузке печатает предупреждение о `qwen3_tts` и пустом model type tokenizer. В этом зафиксированном профиле после предупреждения успешно загружаются tokenizer/weights и создаётся аудио. Предупреждение не скрыто и не считается доказательством качества произношения.

## Калибровка длины русского сценария

В сохранённом ручном RU-сценарии 198 слов, длительность с межрепличными паузами 124.07 с. Наблюдаемая скорость составляет 95.75 слова/мин. В отдельном E2E-прогоне `ea0c6934ded44e15` root-агент посчитал 398 слов в сценарии. Итоговый `podcast.audio.json` подтверждает 314.97 с, то есть около 75.82 слова/мин. При таком разбросе прежний ориентир 135 слов/мин завышает необходимый объём сценария.

Для следующего RU-черновика разумен предварительный ориентир 85 слов/мин, с диапазоном чувствительности 76–96. Это оценка двух коротких сценариев с Ryan/Vivian, не гарантия целевой длительности. Фактический результат всегда измеряется после синтеза. Для допуска ±10% нужен цикл содержательной правки сценария по измеренному результату и повторной сборки изменённых реплик. Скорость текста не заменяет такую проверку.

## Редактура и восстановление после предела генерации

Дополнительный E2E-подкаст на 3 минуты, draft job `ec6188614d214f0c`, revision 1, выявил реальный сбой Qwen3-TTS. Render job `d6df1c9413df459a` остановился на пятой реплике (index 4, host): генерация дошла до 1500 токенов. Незавершённый сегмент не был опубликован, четыре предыдущих WAV сохранились. Причина достижения лимита внутри модели не установлена. Длина этой реплики сама по себе не превышала входное ограничение renderer.

Через общий `service.edit_draft` создана revision 2. Только проблемная реплика разделена после предложения «Двенадцать основных балок сохранили.» на две последовательные реплики host. Их текст, соединённый одним пробелом, точно совпадает с исходным. Speaker и citations сохранены, остальные реплики не изменены. Модель, checkpoint, голос и настройки генерации остались прежними. Это явная редактура сохранённого сценария, а не автоматическое исправление качества речи.

Новый render job `1a81eda4dc634c4c` успешно собрал 9 реплик: 4 готовых сегмента переиспользованы, 5 новых синтезированы. Длительность по PCM frames итогового WAV составила 203.2 с, wall time 35.304 с. MP3 полностью декодируется FFmpeg без ошибок. Итог лежит в `/private/tmp/brofessor-e2e/jobs/1a81eda4dc634c4c/podcast.mp3`.

Результат на 12.89% длиннее цели 180 с. Поле `duration_matches` равно false, в зарегистрированном артефакте сохранено предупреждение о расхождении более 10%. Значит, редактура восстановила конкретный сбой и подтвердила переиспользование сегментов, но не закрыла критерий целевой длительности. Прослушивание на повторы, пропуски, тембр и ударения по-прежнему не выполнено.

Теперь ошибка renderer указывает номер реплики для пользователя, индекс с нуля и speaker, например `Speech turn 5/9 (index 4, host): Speech hit the generation limit`. Дополнительный offline тест проверяет этот контекст, удаление незаконченного сегмента, сохранение предыдущего checkpoint и его повторное использование. Финально `tests/test_media.py`: 11 passed, Ruff check/format passed.
