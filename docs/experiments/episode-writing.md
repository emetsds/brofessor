# Написание подкастов: оригиналы, связность и проверка сценария

04.11.2026. После разбора критика пользователь разрешил реализацию и ограниченное сравнение. Рабочее дерево сохранено, commit/push не выполнялись. Все реальные вызовы использовали стабильный Codex CLI 0.162.1 с подписочной авторизацией; API billing не включался.

## Продуктовое решение

Обычный автор остаётся по умолчанию: `dialogue_version=3`, `reading_version=2`. Сравнение не показало достаточного выигрыша достоверности для смены default. Новая цепочка доступна явно через «Параметры написания → Расширенная работа с источниками (эксперимент)» или `podcast --writing-method originals`. Этот выбор замораживает `dialogue_version=4` и `reading_version=3`; он также наследуется новыми выпусками соответствующей серии. Прежние задания, prompts, checkpoints и публичная схема Podcast сохраняются.

Вариант 4 передаёт автору раздела обязательные оригиналы по ID из плана и доступный соседний контекст того же источника. Имена и локаторы сохраняются в заметках. План содержит цель слушателя, относительные веса разделов, различия источников и возможность сообщить о недостатке материала. В том же ответе раздела приходит ограниченная редакционная память о сказанном; она не является фактическим evidence и не попадает в публичный сценарий.

Общий prompt раздела ограничен 90 тысячами символов. Обязательные оригиналы не обрезаются; невместившийся обязательный набор даёт ошибку, пропущенное дополнительное соседство перечисляется явно. При коррекции пакет пересчитывается с учётом фактического первого ответа; обязательными остаются и исходные ID раздела, и все ID, уже использованные в ответе. Это закрывает найденное критиком застревание большого первого ответа в checkpoint при фиксированном резерве для correction.

Отдельная «Проверить сценарий по источникам» работает для любого сохранённого подкаста. CLI: `draft check ID --revision N --wait`, чтение отчёта: `draft check-report CHECK_ID`. Задание `check_podcast` использует прежний worker и закрепляет редакцию, source IDs и текущую текстовую модель задачи. Оно не переписывает сценарий и не является обязательным разрешением озвучки.

Проверка возвращает `supported`, `issue` или `needs_context`, точный текст спорного утверждения и дословные выдержки. Выдержки проходят существующую проверку подстроки оригинала. Отсутствие подтверждения в ограниченном пакете не означает, что утверждение отсутствует во всей книге. Отчёт перечисляет рассмотренные, ожидающие и невместившиеся реплики, использованные источники и пропущенный дополнительный контекст. Пустой список замечаний не объявляется заключением о достоверности. Принятые пакеты сохраняются при отмене/ошибке; resume использует прежнюю редакцию и модель.

## Ограниченное сравнение авторов

Воспроизводимый генератор корпуса и протокол: `tools/compare_episode_writers.py`. Материал полностью вымышленный, создан для этого опыта и не содержит пользовательских источников. Три документа — исходный отчёт, июньское уточнение и независимый обзор. Извлечено 61 980 символов, 15 фрагментов. Заранее размечены 30 положений: условия измерения, отрицания, поправки чисел, нерешённое расхождение времени, непроведённые проверки и границы выводов.

Общие заметки и четырёхчастный план закреплены один раз. Сравнивались два автора при прямом и обратном порядке evidence, RU, цель 2 415 слов. Выбор модели — default исполнителя Codex, одинаковый в настройках всех вызовов; точный model ID адаптер не зафиксировал. Это ограничивает воспроизводимость на другом окружении. План нового формата для продуктового пути дополнительно проверен отдельным реальным вызовом; он правильно отличил исправленные 12→10 / 5→5,4 от нерешённого 08:00/09:00.

До раскрытия mapping агент-критик прочитал все уникальные сценарии и сверил их с оригиналами и ID из SQLite, открытой только для чтения. Он не читал mapping, prompts и код сравнения до фиксации вердикта.

Неправильных ID и явно неполных составных ссылок критик не подтвердил. B/C получили небольшое редакционное предпочтение: чище русский текст и немного меньше повторных объяснений. Все варианты избыточно повторяют формулы вроде «учебная интерпретация».

Это три уникальных текста, а не четыре независимых испытания. Новый автор собирает контекст по ID плана, поэтому перестановка общего evidence не изменила его prompts; B использовал checkpoints C. Сравнение оценивает весь пакет изменений, не отдельный вклад памяти или оригиналов.

Входы написания обычного выпуска — в среднем 71 928 символов, нового — 116 560: **на 62% больше**. Это размер входов, не денежная стоимость и не замер токенов. Время четырёх запросов автора: около 230 секунд у обычного в среднем и 225 секунд у нового; точность такого малого замера не позволяет объявить ускорение. Сжатые заметки этого корпуса короткие, а оригиналы содержат много повторов, поэтому экономии входа здесь нет.

## Проверка отчёта на контролируемых ошибках

В отдельной сохранённой редакции шесть реплик: три правильные и три с намеренными ошибками — испытание при паводке, подмена наблюдаемой нагрузки доказанным пятидесятилетним сроком и сохранение отменённого числа двенадцать. Один настоящий `CheckBatch` обнаружил все три ошибки, на трёх правильных репликах замечаний не дал. Все возвращённые выдержки прошли проверку дословности. Это маленькая проверка управляемых дефектов, не оценка точности/полноты аудита на реальных книгах.

Весь опыт сохранил лимит 30 вызовов: **18 успешных генераций и один технический отказ sandbox до генерации**. Принятые вызовы: три чтения, общий план, восемь обычных частей, четыре части нового автора, новый план и один аудит. Озвучка не запускалась.
