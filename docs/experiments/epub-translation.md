# Первая проба перевода EPUB с сохранением оформления

04.11.2026. Первый завершённый шаг P1 из [единственного плана реализации](../implementation-plan.md#p1-перевод-книг-с-сохранением-оформления). Это техническая проба короткой главы и оценка PDF-кандидата по исходникам. Перевод целых книг и пользовательское задание CLI/UI этим опытом не реализованы. Проверка озвучки отложена до отдельного сигнала пользователя.

**Последующее продолжение 04.11:** [реализованы терминология и ранний путь EPUB через worker/CLI/UI](book-terminology.md). Ниже сохранены результаты именно первой технической пробы; её кеш не используется как продуктовый механизм версий/продолжения.

## Материал и условия

Собственная синтетическая глава **Reliable sensor ingestion**, исходники в `tests/fixtures/translation/`. Все тексты, CSS и SVG написаны для brofessor и распространяются под MIT репозитория. Использованных книг, чужих иллюстраций, внешних шрифтов и пользовательских материалов в fixture нет. Источник упакован как reflowable EPUB 3, порядок чтения задаёт spine.

В проекции 43 переводимых блока, около 620 слов с учётом заголовков/оглавления и без защищённого кода/формулы. Есть повторяющиеся термины, два значения `log` (журнал / бревно) и `head` (напор / руководитель), отрицания, числа и единицы, выделения, таблица, сноска с возвратом, SVG-иллюстрация, MathML и код. Глоссарий из восьми записей написан вручную и одинаков для обоих методов. Это **не автоматическое извлечение терминологии**.

Окружение: Python 3.12.13, Pydantic 2.14.2, официальный стабильный `/Users/demets/.local/bin/codex` **0.162.1**. Runner сообщил **`gpt-6.1-sol`, reasoning effort `none`** в обоих вызовах. Первые вызовы использовали CLI-default; фактически выбранная модель записана из заголовка runner в `calls.json`. Финальный probe требует явный `--model` для следующих воспроизводимых сравнений. Использована штатная подписочная авторизация, API-ключи и платный API не подключались. Передавалась только синтетическая глава. Настройки пользователя не менялись.

## Сравнение

| Метод | Вызовы модели | Время, с | Символы prompt / UTF-8 байты | Символы schema | Символы JSON-ответа |
|---|---:|---:|---:|---:|---:|
| Перевод XHTML целиком | 1 | 45,238 | 7 492 / 7 568 | 1 048 | 6 614 |
| Защищённые текстовые блоки | 1 | 53,840 | 12 345 / 12 504 | 498 | 7 072 |

Время включает проверку штатной авторизации и работу runner. Это два наблюдения на одном коротком материале; статистического сравнения скорости нет. Размеры относятся к прикладному prompt/schema до внутренних транспортных инструкций executor. Токены и стоимость не измерялись и из числа символов не выводятся. До них был один неуспешный запуск в OS sandbox (0,671 с); он отдельно сохранён как ошибка запуска, не как перевод.

При первом методе модель возвращает XHTML полностью. При втором `epub_translation.py` выделяет текстовые блоки и доступные текстовые атрибуты, а inline-разметку заменяет маркерами. Модель возвращает только текст с прежними ID. Код проверяет точное покрытие, порядок маркеров, непустоту исходно непустых spans и сохранность числовых значений, включая знак и допустимую смену десятичного разделителя. Теги, атрибуты ссылок, пути, стили и ресурсы восстанавливаются из исходного снимка. Чужая разметка в ответе экранируется как текст. Создание нового файла атомарно; оригинал, в том числе через symlink/hardlink, нельзя выбрать выходом.

**Решение для дальнейшей реализации — защищённые блоки и локальная сборка.** Здесь у них примерно на 65% больше входного текста и на 19% больше времени. Превосходства в качестве перевода опыт не показал: оба метода справились с коротким примером. Основание выбора — проверяемые локальные гарантии структуры, отдельные адресуемые блоки для дальнейших исправлений и отсутствие нового framework/зависимостей. Полный XHTML остаётся контрольным методом в probe; производственного fallback между ними нет.

## Что действительно проверено

Для обоих результатов программно сравнены набор ресурсов, дерево XHTML и непереводимые атрибуты, исходные CSS/SVG, содержимое кода и MathML. Локальные ссылки и anchors разрешаются. Порядок spine сохраняется; новая книга получает отдельный identifier, язык и `dc:source` с идентификатором оригинала. Таблица, подпись, сноска, доступные `alt`/`title`/`aria-label` и оглавление переведены. У результата сохранена карта исходных XML-позиций с SHA-256 оригинала; это внутренние локаторы проекции, не новые HTML anchors.

**EPUBCheck 5.4.0**, запущенный через OpenJDK 24.0.2, проверил исходник и оба перевода: **0 ошибок, 0 предупреждений**. Его фактическое сообщение — проверка по правилам EPUB 3.4. Это проверка формата, не смысловой точности. EPUBCheck скачан с [официального релиза](https://github.com/w3c/epubcheck/releases/tag/v5.4.0), имеет [MIT-лицензию](https://www.w3.org/publishing/epubcheck/), используется только для QA и не добавлен в зависимости приложения. SHA-256 ZIP: `33350c61038e71dfb3d45a76aed04bf5481e6d5500cb780f6e98db8bbd15a28c`.

Оба перевода целиком сверены агентом с исходными текстами; отдельного внешнего редактора в опыте нет. В этом материале не обнаружены пропуски предложений, смена чисел, потери ключевых отрицаний или смешение проверяемых значений терминов. Обе версии сохраняют запрет подтверждения до durable commit, допустимость потери неподтверждённой записи, ограничение результата конкретной установкой и исключение разрушения носителя. Baseline оставил международные `V/s/m/ms` и десятичную точку; блоковый метод локализовал их как `В/с/м/мс` и запятую. Это допустимые варианты записи, а не доказательство различия смыслового качества. Формулировки вроде «действительная контрольная точка» можно улучшить редакционно; автоматический контракт их не оценивает.

В браузере просмотрены полный исходник и оба перевода при ширине 900 px; блоковый результат дополнительно при 530 и 390 px. Видны кириллица, выделения, строки таблицы, иллюстрация, формула и исходный код; перекрытий/обрезки не обнаружено, при 390 px горизонтального переполнения нет. Проверены кликами оглавление → раздел, ссылка на таблицу, сноска и возврат. Скриншоты лежат рядом с результатами. Просмотр XHTML в браузере **не заменяет проверку EPUB в целевой читалке**, которая остаётся частью последующей приёмки целой книги.

126 offline-проверок по границам EPUB/import/executors прошли. В них проверяются точная реконструкция, сохранность снимка/оригинала, текст и доступные атрибуты, вложенный mixed content, отклонение потерь/дубликатов/выдуманных ID, чисел и маркеров, неизменность прежнего файла при плохом ответе и явный отказ для неподдержанного входа. Это отдельные свидетельства от двух настоящих модельных вызовов. Аудио и остальные продуктовые workflow не перегенерировались.

## Оценка BabelDOC для PDF

Изучены исходники стабильного **BabelDOC 0.6.4**, а не установленный интеграционный путь. [Релиз](https://github.com/funstory-ai/BabelDOC/releases/tag/v0.6.4), [зависимости и лицензия AGPL-3.0](https://github.com/funstory-ai/BabelDOC/blob/v0.6.4/pyproject.toml). SHA-256 исходного ZIP: `34febc0a98fefe5b911798878eba05e645d940b16bc044f51558b95c8fed2e4a`.

[`TranslationConfig`](https://github.com/funstory-ai/BabelDOC/blob/v0.6.4/babeldoc/format/pdf/translation_config.py) принимает `BaseTranslator` и отдельный переводчик терминологии. В [`BaseTranslator`](https://github.com/funstory-ai/BabelDOC/blob/v0.6.4/babeldoc/translator/translator.py) есть точки расширения `do_translate` и `do_llm_translate`. Поэтому, **по анализу интерфейса**, мост к `executors.generate` с текстовой JSON-обёрткой возможен без OpenAI API-биллинга: существующий CLI по-прежнему владеет официальной подписочной авторизацией, Ollama использует свой выбранный сервер. Совместимость такого моста с реальным PDF-проходом не проверена. Нужно учитывать probe `do_llm_translate(None)`, идентичность кеша и bounded/concurrent вызовы; готовый адаптер не заявляется.

У кандидата собственные layout-модель, шрифты, кеши и многочисленные зависимости. В изученной конфигурации отсутствие переданной layout-модели вызывает её загрузку через `DocLayoutModel.load_available`. Метаданные ресурсов содержат сетевые URL. Карточка [используемой ONNX-конверсии DocLayout](https://huggingface.co/wybxc/DocLayout-YOLO-DocStructBench-onnx) указывает Apache-2.0; это не завершённая проверка лицензий всего набора. Шрифты и прочие ресурсы из [BabelDOC-Assets](https://github.com/funstory-ai/BabelDOC-Assets) отдельно не принимались и не скачивались. Нельзя выводить их лицензию из лицензии основного кода. В [официальном README](https://github.com/funstory-ai/BabelDOC/tree/v0.6.4#readme) перевод таблиц помечен экспериментальным.

**BabelDOC остаётся кандидатом, в MIT-приложение не встроен.** Скачаны только исходники для чтения. Не выполнялись установка его зависимостей, layout-инференс, загрузка весов/шрифтов, PDF-перевод или проверка кириллицы и переполнений. Это оценка реализуемости и границ следующей PDF-пробы, не положительная приёмка PDF.

В новом clone остаются синтетический fixture, экспериментальное ядро, probe и этот отчёт. Для нового сравнения выбрать отдельную выходную папку и явно закрепить модель:

```sh
BROFESSOR_CODEX_BIN=/path/to/stable/codex uv run --no-sync python tools/probe_epub_translation.py \
  --provider codex --model gpt-6.1-sol --output outputs/epub-translation-next
uv run --no-sync pytest -q tests/test_epub_translation.py tests/test_sources.py tests/test_executors.py
```

Политика упаковки опирается на [EPUB 3.3](https://www.w3.org/TR/epub-33/): пакет, spine, XHTML, навигация и ресурсы сохраняются раздельно. Новые Python-зависимости не добавлены. Шрифты в fixture не встроены; браузер использовал системный serif/monospace.

## Границы прототипа

Явно отвергаются EPUB 2/NCX, fixed layout, несколько packages, шифрование/обфускация/подписи, scripted content, media overlays и XML с DTD/entities. Читаются только объявленные XHTML-документы; код, MathML и иллюстрации сохраняются, надписи внутри картинок не переводятся. Inline-маркеры пока нельзя переставлять: сложная грамматика с перестановкой вложенных выделений требует отдельного решения. Проверка чисел консервативна и не является проверкой единиц измерения, отрицаний или смысла.

Рабочего автоматического словаря, выборочного обновления по смыслу термина, сохранённых пользовательских редакций перевода, ограниченных пакетов целой книги и задания в общей очереди пока нет. Кеш probe хранит ответы сравнения и не выдаётся за checkpoint/revision-механизм продукта. Поддержка Claude/Ollama для перевода проверена только на уровне существующего executor, новых реальных переводов ими не выполнялось. Следующие критерии остаются в P1 общего плана.
