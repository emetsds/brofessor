# Транспорт Ollama через Pydantic AI

07.11.2026 по запросу пользователя заменён собственный транспорт инференса Ollama.
`infrastructure/text/runners.py` использует готовые `OllamaModel` / `OllamaProvider`
и `pydantic_ai.direct.model_request_stream`. SDK формирует native structured-output
запрос к `/v1/chat/completions` и разбирает SSE. Прежние `_ollama_chunk` и ручная
сборка NDJSON удалены. Контракт общего `generate(prompt, schema, ...)` сохранён.

## Границы и зависимости

- Закреплён `pydantic-ai-slim[openai]==2.66.0`; lock добавил OpenAI SDK 3.46.0,
  tiktoken 0.14.0 и jiter 0.19.0. HTTPX2 2.16.0 теперь объявлен прямой зависимостью.
  Лицензии проверены по установленным distributions, notices обновлены.
- SDK получает явный IP:port выбранного Ollama и фиктивный ключ. Переменные
  OpenAI/Ollama API, proxies и redirects не перенаправляют источники. Подписочные
  Codex/Claude adapters и их авторизация не менялись.
- До передачи текста прежний preflight проверяет `/api/status`, `/api/tags` и
  `/api/show`: cloud отключён, модель установлена и не указывает на remote weights.
  Прежние блокировка модели, отмена и общий deadline охватывают запрос.
- SDK retries выставлены в ноль, инструментальная телеметрия выключена. Ограниченный
  HTTP-поток останавливается до накопления ответа сверх 8 MiB, включая reasoning.
  Запрашивается identity encoding; сжатый ответ отвергается до декодирования,
  чтобы сжатие не обходило лимит. При отказе исходный текст не попадает в diagnostic.
- Требуется явный `finish_reason`; принимается только `stop` с текстом без tool calls.
  Приложение по-прежнему проверяет JSON, выходную модель, язык и исходные цитаты.
- Для моделей, объявляющих поддержку `think=false`, отправляется совместимый
  `reasoning_effort="none"`; остальные используют свой default.
- JSON schema transformer SDK отключён: сохраняются исходные titles, defaults,
  nullable/nested fields и ограничения. System/user сообщения берутся из прежних
  frozen prompts. Алгоритм checkpoint keys и пользовательские редакции не менялись.

Основания: [готовый OllamaModel](https://pydantic.dev/docs/ai/models/ollama/),
[Direct API](https://pydantic.dev/docs/ai/core-concepts/direct/),
[совместимый API и reasoning control Ollama](https://docs.ollama.com/api/openai-compatibility).
Реальные контракты также сверены с исходниками установленной версии 2.66.0.

## Offline и установленный пакет

В тестах используется настоящий SDK; подменён только HTTP transport. Прежние
проверки preflight, адресов, cloud/remote-моделей и redirects сохранены. Тесты
отмены/deadline теперь закрывают настоящий HTTP-поток SDK вместо подмены всей
функции запроса. Дополнены контролируемые отказы: tool calls, обрезанный/невалидный
ответ, HTTP 503 без скрытого retry, подмена endpoint/key окружением, превышение
лимита до буферизации, сжатый ответ и сохранение r2 при replay без нового запроса.
Защита не завязана на число внутренних вызовов вспомогательных функций.

- Адресный набор runners/navigation/collections/pipeline/maintenance/prompts:
  **241 passed / 27,25 с**.
- Полный набор до последнего контроля сжатия: **752 passed / 61,79 с**.
- После добавления контроля сжатия финальный набор runners:
  **82 passed / 7,98 с**; полный набор повторно не запускался.
- Ruff check/format (300 файлов) и `git diff --check` прошли.
- Окончательный wheel собран штатным `uv build --offline --wheel`. В новом
  окружении Python 3.12.13 установлены wheel и закреплённые core/dev зависимости.
  Проверены импорт SDK и нового модуля из `site-packages`, CLI `--help` и
  **82 runner-проверки / 10,73 с** с cwd вне checkout и `python -I`.
  Первоначальная offline-установка остановилась из-за отсутствующих wheels в кеше;
  недостающие публичные пакеты скачаны обычной установкой. QA и тесты в wheel не входят.

## Настоящий локальный контроль

Временный Ollama **0.40.6** на `127.0.0.1:11436` запущен с `OLLAMA_NO_CLOUD=1`,
context 32768 и одним параллельным запросом. Использованы уже установленные веса
`qwen3.8:27b-q4_K_M`, digest
`25b843619e944cd0ae6069f94ff4e5e26a16e109ccbc0a66a0f05979ed70098e`.
Веса не скачивались; постоянный сервер, preferences и credentials не менялись.

Синтетический Markdown сообщает 12 ms при 48 запросах/с на одном узле, прежние
35 ms и отсутствие подтверждения свойств кластера/устойчивости к потере питания.
Настоящий worker выполнил `ask` **a9c236ca3d3247cf** через новый транспорт за
**61,495 с**, включая холодную загрузку модели. В журнале сервера один
`POST /v1/chat/completions`. Ответ верно передал текущие условия и границы;
две дословные цитаты и неизменность исходника сверены. Валидность JSON отдельно
не считалась доказательством содержания.

После сохранения пользовательской r2 временный сервер остановлен. Повтор pipeline
завершился с единственным прежним checkpoint, без нового inference и изменения
его SHA-256, сохранив r2. Временный сервер завершён; данные пробы остались вне Git.

Это проверка одного короткого вопроса и модели, а не benchmark скорости,
приёмка целой книги или всех Ollama-моделей. После финального добавления запрета
HTTP-сжатия реальная генерация повторно не запускалась; окончательный код проверен
offline и из установленного wheel. UI в браузере, TTS, PPTX и облачные runners
в этой работе реально не запускались.
