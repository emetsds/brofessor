# Реализация brofessor

Состояние: 01.11.2026. Пользователь принял упрощения ревью и поручил реализацию. Это единственный список задач. [Требования](requirements.md), [архитектура](architecture.md), [исследование](research.md).

## Принятые упрощения

- SQLite и отдельный worker входят в первый рабочий срез. Он развивается в продукт, отдельного прототипа на выброс нет.
- CLI и Streamlit используют общие функции приложения. Отдельный HTTP-сервер не нужен.
- Codex, Claude и Ollama - три адаптера одного задания. Дополнительного протокола `prepare/accept`, состояния ожидания host-agent и установщика skills нет.
- Единственный worker удерживает OS-lock. Транзакции, checkpoints, отмена и восстановление нужны. Временные аренды и механизм передачи работы второму worker не нужны.
- Workspace хранит файлы и SQLite с относительными путями. Перенос закрытого каталога достаточен для начала. Архивного формата и отдельных export/import интерфейсов нет.
- Первый TTS-пилот выполнен на одной модели. По новому запросу пользователя добавляются выбор и скачивание поддерживаемых TTS-моделей из UI и CLI.
- По запросу пользователя генерация PPTX переносится в Python через `python-pptx>=1.0.2,<2`. Установка и CI используют только Python-зависимости, отдельный framework для рендера не добавляется.
- Подкасты и слайды не ждут завершения исследовательского чата. Предположительные будущие функции не включаются в задачи.

## Проекты и выбор TTS-моделей

Добавлено по запросу пользователя от 01.11.2026. Реализовано и проверено в этом рабочем срезе.

**Проект** — набор источников и связанных с ними результатов переработки: ответов, черновиков, подкастов и презентаций. Пользователь работает с именованными проектами по привычной модели NotebookLM. Существующий `workspace` остаётся хранилищем одного проекта.

- [x] **Хранение проектов отдельно от приложения.** Позволять выбирать папку для проектов вне каталога установки или checkout brofessor. Обновление и перемещение приложения сохраняют доступ к данным. Поддержать открытие существующего workspace как проекта с сохранением источников, истории, правок и результатов.
- [x] **Выбор проектов.** Добавить создание, список и переключение именованных проектов в UI и CLI. При выборе показывать только источники, задания и результаты этого проекта; запоминать последний открытый проект. Проверить два независимых проекта во внешней папке, переключение между ними и повторное открытие после перезапуска приложения.
- [x] **Выбор и скачивание TTS-моделей.** Показывать поддерживаемые модели, их языки, совместимость с Mac, размер скачивания и наличие на диске. Из UI и CLI позволять скачать выбранную модель с видимым прогрессом и ошибками, затем выбрать её для озвучки. Сохранять выбор в задании; переиспользовать общие установленные веса между проектами. Проверить скачивание, повторное использование без сети и озвучку выбранной моделью.

Проверено: 200 offline-тестов, Ruff, содержимое wheel и настоящий браузер. Две модели Qwen3 4-bit установлены в общий пользовательский каталог вне приложения; обе создали RU/EN аудио без сети. [Результаты и границы проверки](experiments/projects-and-models.md).

## Проверки

Основные команды: `uv run --extra ui pytest`, `uv run ruff check .`, `uv run ruff format --check .`. Обычные тесты не требуют подписки, сети или весов. Настоящие вызовы и артефакты записываются отдельно в `docs/experiments/`.

Пункты отмечаются только после фактической проверки. Валидная JSON schema не доказывает обоснованность, а наличие PPTX/MP3 не заменяет проверки содержимого и качества.
