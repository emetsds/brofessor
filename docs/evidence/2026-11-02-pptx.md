# Editable PPTX: content types and capacity

Historical report. Current requirements and boundaries are in the [specification](../specification.md); decisions and cancellations are in the [Decision log](../decision-log.md). References to later stages describe the state at the time of the experiment.

Checked 02.11.2026 on an Apple Silicon Mac, Python 3.12.13, `python-pptx==1.0.2`, Pillow 12.3.0. The final M2 presentation item is complete. This verifies the listed examples and renderer behavior; this run does not establish full v1 acceptance.

## Application behavior

One `models.Slides` now describes the text runner's draft, the editor, and render input. Slides support lists, a native table, or a linear diagram of 2–5 steps. Tables are limited to six columns and eight data rows. Two short bullets may accompany a visual block. Valid old bullet-only drafts are accepted without migration. Arbitrary graphs, data charts, and a template library are outside this slice.

A separate small `slides.py` encapsulates text measurement, layout selection, and atomic writing. `media.render_slides` preserves the existing entry point. The core and worker are shared by CLI/UI; the model does not specify coordinates, XML, or office-application commands. No new services or Node/npm were introduced.

Pillow measures the installed font, including bold; selection order is Arial, Liberation Sans, DejaVu Sans. The checked Mac used Arial. Minimum sizes are 28 pt for titles, 20 pt for bullets, and 18 pt for tables and step labels. Footer/page number sizes are 11/12 pt. Long step labels switch the diagram to vertical layout. Line spacing is explicit. If text does not fit, the error names the slide; the original words, draft, and previous PPTX are preserved. There is no automatic text loss or addition of slides.

Notes contain the original explanation and all source IDs; the pipeline appends the source filename and original locator. The slide shows a reference count and where the references are stored. 50 long IDs and long multi-paragraph notes were checked. The model can still misinterpret a fragment: a valid ID alone does not support a claim.

## Visual checking and editability

All 24 final slides were inspected individually after PPTX → PDF → PNG conversion:

| Set | Slides | Check |
|---|---:|---|
| Book RU | 6 | Cyrillic, long titles, vertical diagrams, lists |
| Book EN | 6 | Substantive table, horizontal diagram, lists |
| Synthetic RU | 6 | 6×8 table, table with two bullets, empty cells/units, five steps, dense text, long references/notes |
| Synthetic EN | 6 | The same matrix in English |

Synthetic numbers serve only to check layout. In the final examples, text fits, table rows are readable, and footers are separate from body text. All 24 slides use native objects, without images. Programmatic checks cover object boundaries, preservation of every title/bullet/cell/step in PPTX and extracted PDF text, original notes, and all references. Resulting body sizes are 19–23 pt and titles 32 pt; 18/20/28 pt are permissible minima, not instructions to always shrink to them.

A separate copy of the English PPTX was edited without rebuilding from the plan: a table cell, a block label, and notes. After saving and reopening, the texts and 19/23 pt sizes persisted. The copy was converted to PDF again, and both edited slides were inspected. An automated AppTest additionally edits a table and step in the UI, switches language, and saves a revision; the CLI renders that exact revision with the original locators.

QA found two defects before final verification. The office converter initially substituted Liberation Sans for Arial. An isolated fontconfig was directed at Mac system fonts, after which Arial/Arial Bold (and OpenSymbol for bullets) were confirmed in all final PDF resources. In dense text, inherited line spacing caused overflow; exact spacing in points is now specified. Native diagrams also have shadows inherited from the office theme disabled.

The temporary QA tool was environment-supplied LibreOfficeDev **26.8.0.0.alpha0**, build `2c87e51eeaa2b413ff4ae097b2705eea1995d8e5`, and Poppler 26.05.0. The alpha was used only for this isolated experiment with separate profiles/fontconfig. The application, installation, and worker do not depend on it; no persistent integration or UI previews were added. Microsoft PowerPoint and Google Slides were not opened manually. PPTX fonts are not embedded, so substitution is possible on another machine and visual checking is required.

## Replacing the Node renderer

Checked 01.11.2026 on Apple M4, Python 3.12.13, `python-pptx==1.0.2`. Dependencies are pinned in `uv.lock`. This replaces the existing application's renderer without a new service or interface.

This is a historical snapshot of the Node replacement. The later [M2 check](2026-11-02-pptx.md) aligned the table/diagram contract with the editor and introduced text measurement with minimum sizes 28/20/18 pt. Shrinking tables to 14 pt, mentioned below, is no longer used.

### What was checked

- `render_slides` works through the same shared CLI/UI path. The JavaScript renderer, `package.json`, `package-lock.json`, and Node/npm were removed from installation and CI.
- A real PPTX is created in a test with an empty `PATH` and subprocess calls prohibited. Unicode, slide order, editable text and table, notes, and citations are preserved. After editing a cell and note, the saved file reopens with those changes.
- A separate wheel was built, installed with pinned Python dependencies in a clean environment, and run outside the checkout with an empty `PATH`. PPTX creation and reopening passed. No office suite is required for generation.
- Write failure was checked with a partially written temporary file: the previous PPTX is preserved and the temporary file removed.
- A subagent review found an incorrect order of list XML elements. This was fixed; the test checks that `buChar` precedes `defRPr`.

### Visual checking

Three presentations were created: three Russian media-pilot slides with a table, four slides from an earlier Codex plan, and three synthetic English slides. They check an ordinary list, a long title, eight bullets, and a five-column, six-row table.

After QA conversion to PDF/PNG, all ten slides were inspected. Initial overflow of the dense table was fixed by shrinking such tables to 14 pt; long titles use 24 pt. In the checked examples, text and tables fit, references and page numbers are visible. LibreOffice is used only for QA and is not a product dependency.

Results are outside Git: `/private/tmp/brofessor-python-pptx-qa`. Synthetic example `bridge-ru.pptx` is also saved in local `outputs/python-pptx/`.

### Verification boundaries

Checking through LibreOffice and Python is not equivalent to manual checking in Microsoft PowerPoint or Google Slides; neither was used in this run. Visual checks apply to the listed examples and do not guarantee layout for arbitrary text within formal limits. Later checking of different content types is presented at the start of this report.

Real text-model calls and speech synthesis were not repeated: their code and saved materials were unchanged. Offline suite: 122 tests; Ruff check and format pass.
