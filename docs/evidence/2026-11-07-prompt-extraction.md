## Что доступно пользователю

**56 UTF-8 `.md`-шаблонов** сгруппированы в `common`, `navigation`, `reading`, `questions`, `reports`, `slides`, `podcasts`, `studies`, `books` и `experiments`. Включены общая граница Codex/Claude/Ollama, инструкции навигационного агента, описание SDK-инструмента, явные подсказки повторного чтения/сужения области, четыре вида отчётов, старые ветки чтения и диалога, перевод и работа с терминологией. Отдельно помечены четыре инструкции developer-проб; они не включаются в обычные задания.

Текст каждого `.md` является инструкцией или явно обозначенным компонентом. Оглавление и `catalogue.json` дают назначение, входные переменные, общие части, выходную схему, условие/версию и место вызова. Метаданные не попадают в сообщения модели. Схемы, JSON-сериализация, бюджеты, поиск исходных данных, валидация и расчёт длины остаются в Python.

Команды `brofessor prompts list`, `show ID`, `preview ID` и `preview --all` работают без модели, сети и проекта. Предпросмотр показывает подстановки, компонент и полные сообщения с runner-границей: единый stdin-текст для Codex/Claude и отдельные `system`/`user` для Ollama. Можно передать JSON переменных, выбрать provider или набор сохранённого задания через `-w PATH ... --job ID`. В последнем случае показываются закреплённые инструкции с примерными входами; это не проигрывание старых материалов проекта. `show --job` выводит точный сохранённый шаблон. Реальный путь редактируемого пакета указан в выводе.

Загрузчик использует стандартную библиотеку: package resources, однократную именованную подстановку, JSON и contextvars. Выражения и код в шаблонах не исполняются. Неизвестные IDs/переменные, пропавшие файлы и незаполненные входы дают конкретную ошибку до соответствующего inference. Буквальные JSON-примеры допустимы, а похожие на подстановки строки внутри исходных данных не интерпретируются повторно. Общая граница runner входит в прежний лимит сообщения 8 MiB.

В речевых адаптерах дополнительных авторских system/instruction-промптов не обнаружено: передаются текст озвучки и данные WAV-референса с расшифровкой. Пользовательские запросы, материалы, эталонные ответы, типовые ошибки SDK и файловой системы — данные/контракты, а не отдельные редактируемые инструкции.

## Сохранность старых и новых заданий

Новые задания из общих сервисов CLI/UI получают `prompt_snapshot` в существующих `params`: применимое семейство шаблонов, полный текст, SHA-256 каждого и всего набора. Новой таблицы, зависимости, очереди или сервиса нет. Контекст набора распространяется на весь pipeline, включая asyncio и `to_thread` runner/агента. Правка `.md` видна новому заданию, регенерации и новым дочерним операциям; явный retry и resume используют сохранённый набор. Идентичность новых checkpoints включает реальные сообщения вместе с runner-инструкциями.

Для заданий без snapshot добавлен неизменяемый `legacy.json` с точным извлечённым набором. Старый алгоритм checkpoint keys сохранён. Архив содержит прежние варианты чтения и сценария; новые Markdown-правки его не меняют. Его целостность и текст проверяются по хешу и историческому синтетическому эталону. Существующие строки jobs не переписываются, пользовательские редакции остаются доступными.

До изменений сохранён исходный код, тесты и tools в `/private/tmp/brofessor-prompts-2026-11-07/baseline`, без пользовательских материалов и `.git`. Тексты и подстановки извлечены из исходных выражений с сохранением порядка, пробелов, разделителей и сериализации. Для всех компонентов подтверждено совпадение на синтетических входах. Исторический [fixture с provenance](../../tests/fixtures/prompts/README.md) защищает именно архив, поэтому обычная редактура текущих `.md` не требует переписывать этот эталон.

Новые проверки защищают точные исторические тексты, однократную вставку исходного текста, literal JSON, неизвестные/пропавшие шаблоны, framing и полный бюджет входа. Через настоящие application services проверены: изменение файла между enqueue и execute; новое задание и регенерация с новым набором; explicit retry со старым набором; повтор исправления термина при ошибочной текущей редактуре; хеширование runner-границы; отказ при испорченном snapshot до inference; старый checkpoint после контролируемого сбоя публикации и сохранение авторской r2 при продолжении.

Wheel собран штатным `uv build --offline --wheel` и установлен с прежними зависимостями в отдельное временное окружение Python 3.12.13 с UI. Вне checkout проверены все `.md`, оглавление, каталог, архив, provider framing и предпросмотр каждого применимого замороженного семейства. Импорт идёт из `site-packages`, а не из исходника. Дополнительный адресный прогон установленного wheel — **114 passed / 2,21 с**, включая промпты, агентную навигацию и pipeline.

Отдельный локальный контроль установленного worker: в синтетическом workspace созданы два `ask` до и после изменения только временной установленной копии шаблонов. Каждый запуск `python -m brofessor.application.worker ... --once` передал свои инструкции через настоящий bounded subprocess/guardian в **контролируемый синтетический executable** вместо vendor CLI. Оба задания сохранили ответы и завершились `succeeded`; повтор пустой очереди не вызвал runner снова. Исходная версия не получила новый текст, новая получила изменения общей границы и операции. Временные шаблоны восстановлены, процессы завершены. QA: `/private/tmp/brofessor-prompts-2026-11-07/worker-check-tlip6hpl/`.
