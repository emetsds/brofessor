## Реализация и выбор

`navigation_harness.py` создаёт настоящий `pydantic_ai.Agent` с типизированным инструментом `retrieve` и выходом `NavigationStep`. SDK выполняет цикл вызовов, валидацию аргументов и ограниченные повторные попытки. Завершение проверяет приложение: найденные поисковые превью не считаются прочитанными оригиналами, а полный охват разрешается только после проверки каждого извлекаемого фрагмента области. Финальный вызов не разрешается совмещать с чтением в одном ответе модели: весь такой пакет отвергается до исполнения и сохранения checkpoint, resume может получить исправленный ответ. `NavigationSession` отвечает за документные операции единственного runtime.

`NavigationModel` реализует публичный контракт `Model` через существующие Codex/Claude/Ollama adapters. Модель возвращает один `NavigationStep`, который мост передаёт SDK как единственный вызов `retrieve` или финальный результат. Структурно неверный шаг отклоняется до кеширования и исполнения. Универсальные `RunnerCall`/`RunnerTurn` и JSON-аргументы внутри строки удалены после KISS-аудита. Встроенные OAuth-провайдеры Pydantic AI и провайдерские SDK extras не используются. Официальные CLI продолжают владеть подписочной авторизацией. Нет чтения `auth.json`, брокера токенов, API fallback или новых серверов/очередей приложения. Alpha `pydantic-ai-harness` не добавлен.

Старый контроллер, выбор runtime по версии и совместимость с прежними форматами продолжения удалены по указанию пользователя. Убраны также начальное восстановление legacy-памяти/наблюдений и специальная обработка старого поля версии в request keys. Текущий Pydantic-цикл продолжает работу по собственным checkpoints, законченная навигация переиспользуется. Отдельного слоя миграции и переключателя runtime нет.

История ограничена исходной задачей и двумя последними полными парами вызовов/результатов. Транспортные timestamps/run IDs не участвуют в идентичности запроса, tool-call IDs выводятся из полного prompt. Исходный контекст фиксируется один раз. Результат инструмента и наблюдение сохраняются атомарно, поэтому повтор цикла после сбоя берёт принятые модельные ответы и результаты инструментов из checkpoints. Общий deadline - 600 с, остаток передаётся каждому runner. Лимит SDK - 24 модельных запроса, один запрос даёт один вызов. Прежние бюджеты документов и исходного текста сохраняются. Токены/стоимость существующий bounded runner не измеряет, эти величины не выдаются за нулевые.

Первое сравнение не подтвердило уменьшение собственного кода или выигрыш в скорости. Последующий KISS-аудит сократил сам мост Pydantic с 212 до 163 строк, убрав общий протокол и неиспользуемую копию истории. Это сравнение двух реализаций моста, не benchmark библиотеки против первоначального контроллера. Документные операции и восстановление по-прежнему нужны. Фиксированные прикладные процессы не перенесены в SDK.

## KISS-аудит и контроль текущего протокола

По запросу пользователя выполнен независимый аудит субагентом и повторный review исправлений. Удалены универсальный пакет вызовов, сериализация JSON внутри строки, неиспользуемая полная история `pydantic-run.json`, legacy-память/начальные наблюдения и специальная совместимость request keys со старой версией. Для одного ответа модели достаточно одного `NavigationStep`. Отдельный лимит количества вызовов SDK убран, поскольку каждый модельный запрос даёт ровно один вызов. Лимиты шагов навигации, контекста и исходных фрагментов сохраняются для текущих задач и восстановления.

Сам мост сократился с **212 до 163 строк**. Общий fake внешнего runner и синтетический каталог вынесены в `tests/collection_helpers.py`. Число проверок навигации/коллекций сократилось с **42 до 30**. Полезная защита удалённых дублей осталась здесь:

| Удалённые проверки | Где остаётся поведение |
|---|---|
| Повторный provider × 3, отдельные CLI/UI-сценарии | `test_collections.py`: три runner, точные цитаты, исполнение CLI и Streamlit-задачи с проверкой результата |
| Повторный отказ автора и прямой cancel | Collections проверяет удаление каталога после отказа автора, harness проверяет отмену через настоящий worker и resume |
| Повторный request budget | `test_full_reading_cannot_finish_with_unread_originals` проверяет SDK request limit и отсутствие частичного draft |
| Старые runtime markers, seed legacy-контекста и файл истории SDK | Соответствующие механизмы удалены. Неверные типизированные действия и finish вместе с read отклоняются без исполнения и отравления кеша |

Восстановление проверено после первого и четвёртого retrieval. Второй случай переигрывает уже принятый запрос после сокращения истории, сохраняя принятые шаги и уникальность внешних prompts. Фиксация `harness_input`, стабильные tool-call IDs, атомарные результаты инструментов и сохранённые оригиналы оставлены как необходимые контракты текущего resume.

Реальный контроль текущего протокола через официальный Codex CLI 0.162.1 / `gpt-6.1-sol`: job **`e58078f8d63b47e8`**, **44,437 с**, **3 NavigationStep + 1 Answer**. Прочитаны River, North и South. Ответ верно различает 12 и 35 мс, называет 48 запросов/один узел и непроверенную потерю питания. Семь точных цитат сверены с тремя оригиналами, все восемь файлов остались прежними. Данные и ledger находятся в игнорируемом `outputs/harness-kiss-2026-11-05/codex/`. Это smoke check одного запроса, статистического сравнения скорости нет. Новый формат реально проверен через Codex. Ollama после упрощения повторно не запускался, Claude по-прежнему не прошёл штатную авторизацию.

## Предшествующий собственный контроллер

05.11.2026. Этот отчёт фиксирует первоначальную регистрацию каталога по одному пути и отбор оригиналов через собственный контроллер версии 1. Использованы прежние Python core, bounded text adapters, SQLite, OS-locked worker и checkpoints. В этом опыте Pi и новый агентный framework не устанавливались, проба Pydantic AI Slim ещё не выполнялась. Последующая [проверка и замена цикла на Pydantic AI](2026-11-05-source-navigation.md) описаны отдельно. Результаты ниже относятся к первоначальному контроллеру и сохраняются как его история.

### Пользовательский путь

В Sources → Add materials указать путь к каталогу документов или vault и подключить его. Либо `brofessor source add /path/to/vault`. Подключение сохраняет путь/ID, не обходит файлы, не извлекает текст и не вызывает модель. На новой задаче коллекция выбрана по умолчанию; пользователь задаёт промпт и формат результата. Например: «Найди результаты текущего эксперимента River, условия и ограничения; отличи предыдущий прогон». Файлы вручную отбирать не нужно.

Во время задачи модель выбирает структурированные действия: обзор, локальный BM25-поиск, чтение исходных фрагментов, исходящие/обратные ссылки, завершение. Приложение выполняет их в пределах выбранных корней. Поддержаны UTF-8 Markdown/TXT, текстовые PDF и EPUB прежнего импортёра. Для Obsidian добавлены wiki links, inline relative Markdown links, заголовки, block references, aliases, tags и backlinks. Неоднозначная ссылка не разрешается молча.

История навигации, выбранные пути и оригиналы доступны в деталях задачи и через `job sources JOB_ID`. Сохранённые цитаты/рендер работают после изменения, перемещения и отключения каталога. Новый запуск обходит текущие документы. Состав файлов фиксируется при старте задачи; байты каждого файла — при первом обращении. Это не общий атомарный снимок диска.

### Границы

- Поиск лексический, без embeddings. Он локально извлекает и кеширует подходящие по области файлы во время задачи; нет обязательного индекса/конспекта при подключении.
- Не более 100 000 поддержанных файлов, 32 MiB текста в поисковой области, 24 модельных ходов, 48k символов navigation context и 80k выбранных оригиналов. При превышении нужно сузить каталог/промпт; принятую работу сохраняют checkpoints. Это не обещание прочитать огромное хранилище за один вызов.
- Для запроса полного чтения модель задаёт `exhaustive` и область; host проверяет все извлекаемые фрагменты до finish и сообщает непрочитанные. Недоступная подпапка/оригинал не допускают полного завершения. Селективный поиск такой гарантии не имеет.
- Скрытые/системные каталоги, symlinks и неподдержанные форматы исключены. Код и Obsidian/Dataview-плагины не исполняются. Внешние ссылки не открываются. OCR и надписи растра отсутствуют.
- Snapshot документов относится к моменту первого чтения каждого файла. Изменение каталога во время задачи не делает снимок атомарным.
- Реальные проверки навигации Claude/Ollama, большой личный vault и общий benchmark качества не выполнены. Существующие contract tests адаптеров не заменяют такую приёмку.
